# Example requests

Use these as examples of the kinds of requests Vision can guide. They are not test results or claims about any specific product.

- “Make this button feel more deliberate, but keep the current brand.” — likely Quick.
- “Help people understand this checkout without changing prices, fees, payment behavior, or consent.” — likely Focused.
- “Review my whole app for design consistency. Tell me the scope before changing anything.” — recommend Full, then confirm scope and approval.
- “Look at this screen and tell me whether it needs improvement.” — assessment only; return findings or NO_CHANGE without edits.
- “These navigation icons feel inconsistent. Keep the existing style if possible.” — inspect the approved icon family first; make no license or installation claim without exact evidence.
- “Can you make this flow clearer on mobile and desktop?” — inspect the actual available layouts and test each relevant viewport; state what could not be inspected.
- “Keep my product's playful character but reduce clutter.” — preserve the product's approved personality and remove only elements without a useful role.
- “Use the model I selected and do not delegate.” — respect the host's actual model controls; report requested and observed model separately.
